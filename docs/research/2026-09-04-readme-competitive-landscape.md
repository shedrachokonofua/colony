### Closed/cloud benchmarks

- [GitHub Copilot cloud agent](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent): researches a repository, creates a plan, changes a branch and opens a PR in an ephemeral GitHub Actions environment. GitHub-only, one branch/PR per task, maximum execution 59 minutes. Merge remains GitHub branch protection/status/optional auto-merge.
- [Cursor Background Agents](https://cursor.com/help/ai-features/background-agents/background-agents): long-running VM agents with repository, dependencies, secrets and network; can plan/edit/run/test and attach evidence to PRs. Human reviews/tests/merges.
- [Google Jules](https://jules.google/): GitHub repo/branch → Cloud VM/Gemini 3 Pro plan → user approval → PR → user merge. GitHub-only and Gemini-only; free tier is 15 tasks/day and three concurrent tasks.
- [Devin](https://docs.devin.ai/get-started/devin-intro): cloud AI software engineer for parallel tickets/features/bugs/testing, with web IDE/shell/browser and PR/code-review workflows. Provider/model-locked commercial service; no cited deterministic merge gate.
- [Factory Missions](https://docs.factory.ai/missions/overview): plans/executes 1–500 features with human goal/approval, reusable skills and continuous validation/re-planning. [Sandbox docs](https://docs.factory.ai/autonomy-and-safety/sandbox) claim macOS Seatbelt, Linux/WSL2 bubblewrap + seccomp, network filtering and allowlists. It is the closest commercial claim to end-to-end mission orchestration, but no cited SQLite/Git-provider truth model or prospective merge algorithm.

## README patterns worth borrowing

1. **Promise above the fold.** Anneal, Ralph, Neo, Aider and Paperclip each state the user outcome in one sentence; link the promise to the actual workflow rather than generic “AI-powered” language.
2. **Show the machine working.** Hero GIFs/videos/screenshots are common (Anneal’s self-clearing board, Ralph’s loop, Sculptor’s desktop, Neo’s terminal, OpenHands’ Canvas). A workflow diagram/table makes autonomy legible.
3. **Make first run obvious.** One command or a short numbered path, followed by supported providers and prerequisites.
4. **Earn trust with boundaries.** Anneal’s unsandboxed-permission warning, OpenHands’ full-host warning, Kilo’s `--auto` warning, and Symphony’s trusted-preview status are more credible than vague safety claims.
5. **Prove something concrete.** Ralph shows its own PRD/loop; Anneal says the repository is built by Anneal; SWE-agent/mini-SWE-agent lead with benchmark evidence; Neo emphasizes tests and evidence.
6. **State status plainly.** Vibe Kanban and Sweep disclose sunset/pivot; Sculptor and Symphony call out preview/experimental status; Plandex discloses cloud shutdown.

## White-space claims for Colony

| Colony angle                                                             | Who already claims part of it                                                                                                               | Defensible distinction                                                                                                                                 |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **GitLab-first, end-to-end MR lifecycle**                                | Symphony has a GitLab issue adapter; Factory and Kilo claim GitLab integrations/review                                                      | Make GitLab repository, branch, MR, approvals and merge the primary path—not an adapter or reviewer bolted onto GitHub assumptions.                    |
| **Deterministic prospective merge gate**                                 | Anneal is the closest; other products open PRs or defer to human/host branch rules                                                          | Publish the exact invariant: evaluate candidate head against the prospective base, then merge only the authorized exact head after independent checks. |
| **One SQLite file + Git provider as truth**                              | Paperclip uses embedded PostgreSQL; Symphony specifies in-memory runtime state; others use app/cloud state                                  | A inspectable, portable local state file reconciled with provider truth is a crisp operational promise.                                                |
| **Bounded scope → architected DAG → parallel branches → verified merge** | Factory, Paperclip, Conductor and NeMoCode each cover pieces; Ralph loops stories sequentially                                              | Own the complete coding-factory lifecycle, with explicit dependency edges and branch-level evidence.                                                   |
| **Strong isolation as a default deployment story**                       | Factory documents OS sandboxing; OpenHands documents Docker/VM; Paperclip’s Kubernetes sandbox is roadmap; Anneal is explicitly unsandboxed | Kubernetes/kata-backed workers plus provider credentials scoped to each task would be materially different.                                            |
| **Role-aware model routing and fallbacks**                               | Kilo, Aider, Plandex, Paperclip and OpenHands support model/provider choice                                                                 | Route architect/implementer/reviewer/regression work by cost/quality policy, with fallback and evidence, rather than merely offering a model picker.   |
| **Durable chain memory and consolidation**                               | Ralph uses progress/AGENTS; Paperclip has persistent state; Copilot has Memory                                                              | Consolidate decisions, review findings and repository facts across the whole DAG, not just per-agent transcripts.                                      |
| **Operator-grade notifications/observability**                           | Slack/GitHub/Linear hooks appear in OpenHands, Cursor, Paperclip and Copilot; NeMo Toolkit offers tracing                                   | First-class ntfy plus OTel spans tied to task, branch, agent, check and merge-decision IDs is a clear product surface.                                 |

Colony should not imply that autonomy means no human control: the most credible positioning is bounded scope, isolated workers, evidence-producing checks, and a merge decision that is deterministic and inspectable.
